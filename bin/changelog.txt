  Lamp column dead time becomes a four-position ladder on Options DIP 5 + 6, superseding the 0.1.8 measurement build. OFF/OFF is the series value at about 65 us (duty 21.8 percent), OFF/ON about 250 us (12.8), ON/ON about 400 us (5.5), and DIP 5 on its own still selects the original MPU timing with no dead time at all (24.5). The phase stays 512 us in all four positions because the dwell absorbs the difference, and 24597 clk is the hard ceiling, so 400 us is as far as this goes. 2026-08-14 13:02  version .2.0
  FA-Control solenoid numbers are 1-based from now on: tile n is driver Qn of the schematic, 21 is the coin counter and 22 the coin door lockout. LISY counts coils that way (lisy_5_28/src/lisy/lisy_w.c, "sol number starts with 1") and so does the original documentation, which makes the previous 0..21 the odd one out - a real LISY host would have hit the second coil when sending 1 and could never reach the 22nd at all, because par1 < N_SOL rejected 22. Four opcode handlers in rtl/fa_control/fa_control.vhd changed (G_STAT_SOL, S_SOL_ON, S_SOL_OFF, S_PULSE_SOL): range test is now par1 >= 1 and par1 <= N_SOL, vector index is par1-1. sol_r stays 0-based, so the top level and its gen_fa_sol wiring are untouched, and lamps (0..83) and switches (0..79) keep their 0 base on purpose - the reason is written into the module header. THE ESP32 SIDE MUST MOVE WITH IT: FA_Control 1.16 or newer. An older web firmware against this bitstream fires the coil one position off, so do not mix. Field procedure: program 0.2.0, check the info display shows 020, connect FA-Control with Options DIP 4 = ON and verify that tile 1 fires Q1, tile 20 fires Q20 and tiles 21/22 are coin counter and lockout; tiles 14 and 18 are the unfitted Q14/Q18 and must do nothing. Second part of this release, comments and manuals only, no logic change: the D2 LED never blinked at the 0.6 Hz both manuals promised and never could. cpu_fetch_cnt counts ROM access BURSTS, not time, so bit 20 yields no fixed frequency at all - 0.6 Hz would need 1.26 M edges per second against a 1 MHz cpu_clk, and the construction caps out at 0.24 Hz. Measured is about 3 s per phase and it depends on the game rom. D3 was right all along at 0.477 Hz, and what looks like a one second blink is its half period. Both manuals, the quick reference and the code comments now say so. cyclone_10_dev_open NEVER hardware tested.

2026-08-20 11:53  version .2.1
  0x2000 is a normal dip position now, sw_state(0), with only bit 6 overwritten by dma_toggle, exactly as PinMAME dipg1_r does it for offset 0. It used to be a fully synthesised byte with bit 7 hard 0 and bits 5..0 hard 1 - that matched the two evaluated bits only with the dip OFF (coin/credit factory setting), so a CLOSED dip 0 was invisible to the game while FA-Control showed it correctly on tile 0 (fa_sw_state comes raw from sw_state). Rom proof in docs/Switch_Reading_Analysis.md: 0x721C is the 0x2000 position of the dip loop 0x7200-0x7229, which collects bit 7 by LDAB/BPL/INCA/ROLA, so bit 7 MUST be the dip; bit 6 is the display sync the rom polls with ANDA #$40 at 0x78BE/0x78C9. NOT RELEASED as a build of its own - superseded four hours later by 0.3.0, which carries this fix. No bitstream and no baseline entry exist for this step; the 0.3.0 baseline note carries its deltas.

2026-08-20 18:08  version .3.0
  Background music over the DFPlayer Mini fitted as Audio1. The output SB_Audio, tied to a constant 0 until now, is a 9600 baud 8N1 uart to the player RX pin - CONFIRMED on the hardware for both boards (pcb PIN_7, dev_open PIN_111). New module rtl/common/dfplayer_cmd.vhd, sender is a second instance of the existing rtl/fa_control/uart_tx.vhd with g_CLKS_PER_BIT 5208, not the GottFA1_PLuS home-made shifter on its own 9600 Hz clock - one clock domain fewer and nothing to add to the sdc. Frame is 7E FF 06 <cmd> 00 <par1> <par2> EF, 8 bytes without checksum, commands 0x42 status, 0x06 volume, 0x17 repeat folder 02, 0x0D resume, 0x0E pause. TRIGGER is the flipper control relay Q12, latch 0x1088 bit 6, the Atari counterpart of the Gottlieb game over relay - proof from the Space Riders manual table 5-6, self test 12 and the Middle Earth rom (7F36 game start, 77BC game over), derivation in docs/Background_Music.md. It is taken from the same mux as the physical coil output, so FA-Control can drive it on the bench, and it drops on tilt, which pauses the music exactly as the original relay behaves. GLITCH_CYCLES re-checks the trigger after 500 ms so a single coil pulse from FA-Control cannot start the music. Enabled by Options DIP 1, read at boot, which was free since the FRAM feature went on hold - the manuals now document it as the music switch. Card layout: a folder 02 with 001.mp3, 002.mp3 ... played in a loop; the same card works on a GottFA1_PLuS. No mixer and no ducking, music and game sound are separate analog paths meeting at the amplifier. This release also carries the 0.2.1 dip fix for 0x2000 that was never released on its own. Memory UNCHANGED at 202752 and pins UNCHANGED at 85 of 89, the acceptance criteria; comb +158 and reg +92 against 0.2.1 for the new module; slack 2.897 -> 1.868, the largest single drop in a while and worth watching at the next feature. HARDWARE: 0.3.0 was programmed and RUNS ON BOTH BOARDS - for cyclone_10_dev_open that is the first time the variant has ever run on hardware. STILL OPEN: the music function itself, whether the player really starts and pauses with the flipper relay. Field procedure: put the card in, set Options DIP 1 = ON, power cycle (read at boot), check the info display shows 030, start a game.
